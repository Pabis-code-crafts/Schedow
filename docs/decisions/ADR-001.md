# ADR-001: Adopt Microservices Architecture From Initial Development

## Status

Accepted

---

# Context

Schedow is being developed as a backend engineering focused project intended to demonstrate real-world software architecture concepts including:

* distributed systems
* service communication
* API gateway patterns
* concurrency handling
* scalable backend design
* event-driven workflows

The primary goal of the project is not only feature development, but also showcasing backend engineering skills and architectural decision-making.

A modular monolith architecture would simplify initial development, but would reduce exposure to practical microservices concepts such as:

* inter-service communication
* database-per-service architecture
* service isolation
* distributed request flow
* API gateway routing

---

# Decision

The platform will adopt a lightweight microservices architecture from the beginning of development.

Initial services:

* API Gateway
* User Service
* Scheduling Service
* Marketplace Service

Each service will:

* operate independently
* own its own database
* communicate through REST APIs initially

Kafka and asynchronous communication will be introduced in later phases once the core synchronous workflows are stable.

---

# Consequences

## Benefits

* Demonstrates practical microservices architecture
* Provides hands-on distributed systems experience
* Enables clearer service boundaries
* Improves understanding of scalable backend systems
* Better showcases backend engineering skills

## Tradeoffs

* Increased development complexity
* Additional Docker and networking setup
* More complex debugging during early development
* Cross-service communication overhead

---

# Future Considerations

As the platform evolves:

* Kafka will be introduced for asynchronous workflows
* Additional services may be extracted
* Observability tooling may be added
* Container orchestration may eventually be explored
